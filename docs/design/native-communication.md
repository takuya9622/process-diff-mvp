# ネイティブコミュニケーション設計

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| 文書状態 | 初回実装へ反映済み |
| 対象 | 組織内チャンネル、メッセージ、案件共有、将来の外部連携境界 |
| 最終更新日 | 2026-08-10 |

## 2. 目的

利用者が業務上の相談や確認を別サービスへ移さず、案件の文脈を保ったままアプリ内で行えるように
します。SlackやGoogle Chatは将来の配送・同期先とし、外部サービスが接続されていなくても、
チャンネル、メッセージ、共有された案件をアプリの正規データとして扱います。

この設計はSlackまたはGoogle Chatの画面を複製するものではありません。業務を完了するために
必要な相談と案件共有へ範囲を限定します。

## 3. 情報設計

組織共通shellのサイドバーを次の責務に分けます。

| 区分 | 項目 | 主な目的 |
|---|---|---|
| 概要 | ダッシュボード | 対応待ちと最近の案件を確認する |
| ワークフロー | 業務を開始、自分の案件 | 業務を実行し、現在地と証跡を確認する |
| ナレッジ | 規定・文書 | 規定、手順、役割、利用システムを探す |
| コラボレーション | コミュニケーション | 相談、確認、案件共有を行う |

差分と変更履歴は引き続き変更フロー内だけに表示し、サイドバーの分類にはしません。
`/documents`はナレッジの入口、`/communication`は会話の入口として分けます。業務要素を開いた
場合だけ、規定・文書の二次ナビゲーションを表示します。

## 4. 初回実装の操作

| 操作 | 保存する正規データ | 結果 |
|---|---|---|
| チャンネルを選ぶ | なし | URLの`channel` search paramから同じ表示を復元する |
| チャンネルを作成する | `CommunicationChannel` | 組織内の相談場所を追加する |
| メッセージを投稿する | `CommunicationMessage` | 投稿者名と時刻を含む会話を保存する |
| 案件を添付して投稿する | `CommunicationMessage.related_case_id` | 会話から同じ組織の案件詳細へ移動できる |

チャンネル削除、メッセージ編集、thread、reaction、既読、mention、ファイル添付、外部同期は
初回実装に含めません。

## 5. routeと状態

| 表示 | route | URLで復元するもの |
|---|---|---|
| コミュニケーション | `/organizations/<organizationSlug>/communication` | 組織と既定チャンネル |
| 選択中チャンネル | `/organizations/<organizationSlug>/communication?channel=<channelId>` | 組織と選択中チャンネル |

メッセージ一覧と案件候補はServer Componentで取得します。チャンネル作成と投稿はServer Actionで
session、membership、organization、`workspace.change`権限を再検証します。投稿成功後だけrouteを
更新し、入力エラーでは本文を保持します。

## 6. データ境界

`communication_channels`は組織内の会話単位、`communication_messages`は投稿本文、投稿者snapshot、
任意の案件参照を保持します。組織IDとチャンネルID、組織IDと案件IDの複合外部キーにより、別組織の
チャンネルや案件を混ぜた投稿をDBでも拒否します。

投稿者の認証済みuser IDと表示名snapshotを分けます。ネイティブ投稿は必ずsession userを保存し、
将来のsystem messageまたは外部投稿は、Connectorで検証・正規化した表示主体を保存できる形にします。

## 7. 外部連携境界

Slack／Google Chat固有のworkspace ID、space ID、message ID、認証情報、cursor、retry、rate limitは
ネイティブテーブルへ追加しません。外部連携を実装するときに、次のIntegration層を別テーブルとして
追加します。

```text
CommunicationChannel / CommunicationMessage
  <-> Connector Mapping + External ID + Sync State
  <-> Slack channel / Google Chat space
```

外部から受信した内容は組織と接続先を検証してからネイティブmessageへ変換します。外部への送信が
失敗してもネイティブmessageは失わず、再送状態はIntegration層で管理します。どちらを正本にするか、
双方向同期、編集・削除伝播、thread mappingは外部連携を実装する変更単位で決定します。

## 8. 権限と表示

- `owner`と`editor`はチャンネル作成と投稿を行える。
- `viewer`はチャンネル、メッセージ、共有案件を参照できるが更新できない。
- すべての取得と更新は認可済みorganization IDに限定する。
- チャンネル名は2〜40文字、説明は120文字以内、本文は1〜2,000文字とする。
- 初回サンプルでは「お知らせ・運用」と「経費・申請相談」を組織作成時に用意する。
- 外部連携が未実装であることを画面に明示し、自動同期できると誤認させない。

## 9. 受け入れ条件

1. サイドバーでダッシュボード、ワークフロー、規定・文書、コミュニケーションを識別できる。
2. 利用者が組織内チャンネルを作成し、URLから選択状態を再表示できる。
3. 利用者がメッセージを投稿し、ブラウザ更新後も同じ会話を確認できる。
4. 利用者が自組織の案件を添付し、メッセージから案件詳細へ移動できる。
5. 別組織のチャンネルIDまたは案件IDを指定した投稿を拒否する。
6. Slack／Google Chat未接続でも1〜4を完了できる。
